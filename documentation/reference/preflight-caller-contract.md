# Preflight caller identity and immutable registry

The pinned action contains the reviewed immutable `consumers.yml`. Caller-supplied mutable registries are unsupported. Updating a framework pin never issues Vault credentials, changes an agent grant, or migrates a serving deployment.

The registry includes the measured source inventory for the 17 ecosystem repositories affected by the 2026-10-06 pin repair. `source-head`, `source-pr` and `source-callers` identify the inspected source; they are provenance, not a substitute for the independently checked actual workflow commit. Ten entries are workflow-only (no observed preflight consumer); six have incomplete explicit consumer declarations. These entries fail closed if passed to this caller-contract action. Missing service/agent/key/condition fields are never inferred from repository names or generic action defaults.

Only `binding-status: eligible` entries can invoke the caller contract. Each must provide its explicit service identity, matching Ops Bot agent, secret reference name, deploy condition, exact HTTPS `/events` endpoint and allowed DNS hosts. The action validates the registry endpoint with the same URL guard and requires the caller to declare the identical URL and `allowed_hosts`. All existing immutable action/caller pins, read-only contract job, Vault address, fork/dependency/secret/ordering/failure-propagation checks remain enforced.

The Muneral binding is derived from the existing canonical workflow at `dbfd7c8c905c7986595ad2b0cec1094fa21c1799` and the CI owner's PR209 source tuple. Its registration removes the measured missing-consumer source refusal; it does not establish live Vault/notification/broker authority or admit any API source change. Other consumer owners must supply authentic missing explicit fields through source review before their incomplete registrations can become eligible. No new identity or secret is minted here.

To adopt, pin both composite actions to the same reviewed reachable commit and add the registry's exact `allowed_hosts` alongside the existing endpoint. Consumer repins remain with the CI source owner. Private registries may still be delivered through a reviewed immutable overlay; no mutable runtime registry or unrestricted URL fallback is accepted.
