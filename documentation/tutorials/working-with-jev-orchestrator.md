# Работа с Jev-оркестратором: практическое руководство

> **Historical: Datarim 2.x only. The commands below are not installed by 3.x.** The `dr-jev` and `dr-claude-jev`
> launchers, `install.py --scope user`, and an exported `TYPESAFE_API_KEY` describe the retired
> user-scope integration. Datarim 3.x installs Jev per project or per host and reads the key from a
> private file: see [INSTALL.md](../../INSTALL.md) and the [Jev CLI reference](../reference/jev-cli.md).

Это руководство отвечает на один вопрос: **что набирать в терминале теперь**, когда к Datarim
добавился оркестратор Jev.

Главное в одной фразе: **ничего из того, что вы набирали раньше, не изменилось.** Jev — это
надстройка, а не замена. Все команды `/dr-*` работают как работали, `claude` и `codex` работают
как работали. Новое — это три дополнительных инструмента, и ими можно не пользоваться вовсе.

---

## 1. Что вообще изменилось

Было: вы выбирали модель сами, один раз, при запуске.

```bash
claude --model opus "сложная задача"      # угадали
claude --model sonnet "простая задача"    # угадали
claude "задача"                           # взяли что было по умолчанию
```

Стало: Jev может выбрать за вас — и, в режиме `--live`, поменять решение по ходу работы, когда
характер задачи меняется (исследование → реализация → тесты → документация).

Jev — это внешний классификатор (TypeSafe System-One), который отвечает на короткие
закрытые вопросы дёшево и быстро (~1 секунда). Он не пишет код и не рассуждает о задаче. Он
только раскладывает её по осям: сложность, риск, нужна ли валидация, какой тир модели хватит.

**Jev — советник, не начальник.** Его решения помечены как advisory; политика остаётся в коде,
а детерминированные запреты Datarim он не переопределяет никогда.

---

## 2. Три сценария: выберите свой

### Сценарий A. «Я не хочу ничего менять»

Ничего не делайте. Продолжайте работать как раньше:

```bash
claude "задача"
codex "задача"
/dr-init  /dr-plan  /dr-do  /dr-qa  /dr-archive
```

Хуки Jev будут тихо подмешивать подсказки в контекст агента. Если Jev недоступен — ничего не
произойдёт, вы даже не заметите. Это проверено: см. § 6.

### Сценарий B. «Пусть Jev выбирает модель за меня»

```bash
dr-claude-jev "задача"
```

Jev оценит задачу, покажет сводку и запустит Claude Code на выбранном тире. Одна модель на всю
сессию — как раньше, но выбор сделан по существу задачи, а не наугад.

### Сценарий C. «Пусть Jev управляет по ходу работы»

```bash
dr-claude-jev --live "задача"
```

Здесь запускается процесс-супервизор. Он следит за работой агента и на границах фаз спрашивает
Jev: «характер работы изменился — нужен другой тир?» Если да и если это оправдано экономически —
переключает модель на живой сессии.

Это единственный режим, где происходит динамика. Остальные — статические.

## 3. Команды: полная карта

### Запуск работы

| Команда | Что делает |
|---|---|
| `dr-claude-jev "задача"` | Jev выбирает тир → запускает Claude Code |
| `dr-claude-jev --live "задача"` | То же + динамическое переключение по ходу |
| `dr-claude-jev --runtime codex "задача"` | То же, но Codex вместо Claude Code |
| `dr-claude-jev --live --runtime codex "задача"` | Codex с динамическим роутингом |
| `dr-claude-jev --mode economy "задача"` | Дешевле: потолок — Sonnet, меньше валидации |
| `dr-claude-jev --mode quality "задача"` | Качество: пол — Sonnet, разрешён Opus, шире контекст |
| `dr-claude-jev --model opus "задача"` | Ваш выбор важнее решения Jev |
| `dr-claude-jev --no-route "задача"` | Запустить без обращения к Jev |
| `dr-claude-jev` | Обычный интерактивный Claude Code |

### Посмотреть решение, не запуская работу

| Команда | Что показывает |
|---|---|
| `dr-jev route --summary "задача"` | Компактная сводка решения |
| `dr-jev route --explain "задача"` | Сводка + полный JSON вероятностей |
| `dr-jev route "задача"` | Только JSON (для скриптов) |
| `dr-jev last` | Последнее решение с полосами вероятностей |
| `dr-jev stats` | Накопленная статистика и расхождения предсказаний с фактом |

### Диагностика и управление

| Команда | Что делает |
|---|---|
| `dr-jev doctor` | Проверка установки |
| `dr-jev doctor --api` | То же + живая проверка TypeSafe API |
| `dr-jev status` | Включена интеграция или нет |
| `dr-jev runtimes` | Какие агентские CLI доступны и как у них работает переключение |
| `dr-jev modes` | Описание режимов |
| **`dr-jev off`** | **Выключить интеграцию полностью** |
| `dr-jev on` | Включить обратно |

### Команды Datarim

Не изменились. `/dr-init`, `/dr-prd`, `/dr-plan`, `/dr-design`, `/dr-do`, `/dr-qa`,
`/dr-compliance`, `/dr-archive`, `/dr-auto` и остальные работают точно как раньше — ядро
Datarim ничего не знает о Jev, зависимость односторонняя.

## 4. Два рантайма: Claude Code и Codex

Один и тот же оркестратор управляет двумя разными CLI. Но переключаются они по-разному, и это
не косметическая деталь.

| | Claude Code | Codex |
|---|---|---|
| Как меняется тир | **в живой сессии** (`control_request` на stdin) | **со следующего хода** (`codex exec resume` с новыми параметрами) |
| Что реально меняется | модель (`haiku`/`sonnet`/`opus`) + бюджет размышления | уровень `model_reasoning_effort` (`low`/`medium`/`high`) |
| Сохраняется ли контекст | да, сессия не прерывается | да, `resume` восстанавливает тред |

Почему у Codex по-другому: у него нет канала управления живым процессом. Зато `codex exec resume`
сохраняет контекст и принимает новые `-m` / `model_reasoning_effort`. Проверено: факт, записанный
до смены effort, корректно вспоминается после.

**Почему у Codex по умолчанию меняется effort, а не модель.** Доступность моделей зависит от
аккаунта — на ChatGPT-аккаунте проверка показала, что доступна только модель по умолчанию, а
остальные отдают HTTP 400. Поэтому портируемый рычаг — effort. Если у вас есть доступ к другим
моделям, назначьте их на тиры:

```bash
export DATARIM_CODEX_MODEL_HAIKU="дешёвая-модель"
export DATARIM_CODEX_MODEL_SONNET="обычная-модель"
export DATARIM_CODEX_MODEL_OPUS="сильная-модель"
```

Тогда Codex будет переключать и модель, и effort.

Рантайм по умолчанию задаётся один раз:

```bash
export DATARIM_JEV_RUNTIME=codex     # или claude
```

## 5. Многоходовое сопровождение

По умолчанию `--live` ведёт один ход. Для длинных задач супервизор может вести работу до конца:

```bash
dr-claude-jev --live \
  --continue-prompt "Continue with the next step. Reply TASK_COMPLETE when finished." \
  --max-turns 8 --max-seconds 1800 \
  "задача"
```

Флаги многоходового режима действуют только вместе с `--live` — без него команда завершится
с ошибкой, а не молча проигнорирует их. Для Codex добавьте `--runtime codex`.

Три независимых ограничителя, каждый закрывает свой класс зависания:

- `--max-turns` — счётчик ходов; не спасёт, если ход не завершается;
- `--max-seconds` — общий лимит по часам; единственная защита от «болтливого, но застрявшего»
  агента, который сбрасывает межкадровый таймаут своей же активностью;
- внутренний таймаут тишины (30 мин) — молчание между кадрами.

Маркер завершения (`TASK_COMPLETE`) проверяется буквально. Угадывать завершение по прозе
ненадёжно: ошибка либо обрывает работу, либо зацикливает её.

Полный набор флагов супервизора:

| Флаг | Назначение |
|---|---|
| `--runtime {claude,codex}` | какой агентский CLI вести |
| `--mode {economy,balanced,quality}` | политика стоимости/качества |
| `--continue-prompt "<текст>"` | включает многоходовой режим |
| `--done-marker TASK_COMPLETE` | токен завершения |
| `--max-turns N` | лимит ходов |
| `--max-seconds N` | лимит по часам на весь прогон |
| `--explain` | полный JSON решения перед запуском |
| `--quiet` | без сводки |
| `-- <args>` | всё после `--` уходит агентскому CLI |

Причина остановки пишется в журнал (`stop_reason`): `done_marker`, `max_turns`, `max_seconds`,
`one_shot`, `idle_timeout`, `child_exited`, `write_failed`, `startup_failed`, `interrupted`
(Ctrl-C), `supervisor_error` (сбой самого супервизора). Вместе с кодом выхода агента и хвостом его
stderr — иначе fail-open путь потом невозможно диагностировать. `dr-jev stats` показывает
распределение причин.

Слова «completed» в этом списке нет намеренно. Каждый обычный выход называет свою причину, поэтому
успокаивающее значение по умолчанию помечало бы ровно прерванные и аварийные прогоны — при отборе
успешных сессий вы получили бы неудачные.

**Особенность Codex.** Если Codex не сообщил идентификатор треда (сбой запуска или аутентификации),
супервизор **останавливается** с `stop_reason: write_failed`, а не продолжает. Причина: без
идентификатора `resume` молча превратился бы в новый тред — каждый ход начинал бы задачу с нуля,
а журнал показывал бы нормальный многоходовой прогон. Потерять прогон громко лучше, чем платить за
работу, которая не накапливается.

## 6. Если Jev не работает

Это спроектировано так, чтобы вас не задеть. Все пути — fail-open: при любом сбое Jev работа
продолжается без его подсказок.

Проверено для каждого режима отказа (нет API-ключа, сломанный конфиг, отсутствующий конфиг,
выключенная интеграция): все хуки завершаются с кодом 0, без трейсбеков, и **детерминированный
порог безопасности продолжает блокировать разрушительные команды**.

Последнее — принципиально. Отключение Jev убирает *советующий* слой, но не защиту.

Порог блокирует небольшой набор катастрофических и необратимых команд, сопоставляя их с
**нормализованным argv**, а не с текстом. Поэтому вариации написания не обходят его:

| Блокируется | Не блокируется |
|---|---|
| рекурсивное принудительное удаление защищённых путей (`/`, `/*`, `/usr`, `/etc`, `/home`, …) — в любом написании флагов (`-rf`, `-fr`, `-r -f`, `--recursive --force`) и под обёртками (`sudo`, `env`, `nohup`) | рекурсивное удаление рабочих путей (`./build`, `node_modules`, `dist/`) |
| удаление домашнего каталога целиком — `~`, `~/`, `$HOME`, `${HOME}`, `~/*` и уже раскрытый путь | удаление *внутри* дома: `~/code/build`, `$HOME/.cache`, `~/Library/Caches/pip` |
| `git push --force`, `git push -f` | `git push --force-with-lease`, `--force-if-includes` — это *безопасные* варианты, блокировать их значило бы подталкивать к обычному `--force` |
| `git reset --hard` | `git reset --soft` |
| `DROP DATABASE`, `DROP SCHEMA` | `DROP TABLE` |

Сегменты составных команд проверяются отдельно, поэтому `cd /tmp && rm -rf /` тоже блокируется.

Порог намеренно узкий: градуированная оценка риска — задача советующего слоя. Ложная блокировка
здесь исправима переформулировкой, пропущенное удаление корня — нет.

```bash
dr-jev off
# перечисленное выше по-прежнему блокируется
```

### Выключить интеграцию

Два способа, оба не требуют правки конфигов и не трогают установленные хуки:

```bash
dr-jev off                    # для всей машины, сохраняется между сессиями
export DATARIM_JEV_DISABLE=1  # только для текущей оболочки
```

После этого Datarim, Claude Code и Codex работают ровно как до интеграции.

### Если что-то ведёт себя странно

```bash
dr-jev status        # включено ли
dr-jev doctor --api  # живо ли API
dr-jev off           # если сомневаетесь — выключите и работайте дальше
```

Правило: **выключить интеграцию должно быть проще, чем её починить.** Если вы отлаживаете
что-то другое и подозреваете Jev — `dr-jev off`, и он больше не участвует.

## 7. Что смотреть, чтобы понять, полезен ли Jev

Не «угадал ли Jev модель» — это плохая метрика, потому что правильного ответа никто не знает.

Смотрите на расхождение между предсказанием и фактом:

```bash
dr-jev stats
```

Ключевая строка — `work broader than the prediction`: как часто фактическая
последовательность фаз оказалась шире, чем предсказанный набор компонентов. Высокий счётчик
означает, что одноразовый роутинг недоописывает задачи — и это аргумент за `--live`, а не за
подкрутку порогов.

Вторая полезная часть — `Decisiveness by axis`: насколько Jev решителен по каждой оси. Оси с
низкой уверенностью и низким процентом применения — кандидаты на переработку вопросов, а не на
понижение порога.

## 8. Частые вопросы

**Нужно ли переучиваться?** Нет. Всё старое работает. Новое можно не использовать.

**Замедляет ли это работу?** Роутинг — около 1 секунды на задачу. Хук укладывается в свой бюджет
4 секунды с трёхкратным запасом.

**Почему переключение модели не происходит после каждого шага?** Потому что смена модели
сбрасывает prompt cache — замер показал полную переоплату контекста (~27 тыс. токенов). Наивный
цикл «спрашивать после каждого шага» потратит больше, чем сэкономит. Поэтому переключение
происходит на границах фаз и с гистерезисом; пороги описаны в
[how-to по control plane](../how-to/claude-code-jev-control-plane.md).

**Почему Jev выбрал Sonnet, хотя задача сложная?** Сложность ≠ Opus. Если Sonnet справится,
платить за Opus не нужно. Посмотрите `dr-jev last` — там видно распределение вероятностей и
причину.

**Можно ли настоять на своей модели?** Да: `--model` всегда важнее решения Jev.

**Что если я хочу Codex по умолчанию?** `export DATARIM_JEV_RUNTIME=codex`.
