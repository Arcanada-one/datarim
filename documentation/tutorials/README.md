# Tutorials — Learning-Oriented Documentation

Tutorials teach through practice. A tutorial is written for someone who has not
used Datarim before: it moves step by step, from simple to complex, and its goal
is to build a skill rather than to explain a concept. The reader performs the
actions and ends up with a working result.

## When to write here

- A user's first encounter with the framework — end-to-end, from install to a
  first completed task.
- A step-by-step lesson for a newcomer with no prior knowledge of the pipeline.
- A hands-on walkthrough where the reader builds something themselves.
- A getting-started flow: the minimum steps to run it and confirm it works.

## When NOT to write here

- A recipe for a specific task, aimed at someone who already knows the basics →
  [`how-to/`](../how-to/)
- Factual lookup — command signatures, flags, schemas, catalogues →
  [`reference/`](../reference/)
- Background, rationale, or design trade-offs → [`explanation/`](../explanation/)

## Naming convention

Kebab-case `.md` filenames describing the learning goal, for example
`getting-started.md`.
