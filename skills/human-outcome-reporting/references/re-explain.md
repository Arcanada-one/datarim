# Read-only re-explanation

Trigger on an explicit user request for a clearer explanation, or `/dr-explain`.
Do not repeatedly invoke this mode because the model guesses the user is confused.

1. Identify the requested result or term. A narrow term question needs a narrow
   answer, not a whole project status report.
2. Read the relevant original request, approved amendments, report and evidence
   under existing permissions. The previous prose identifies what did not land;
   it is not authoritative evidence of execution.
3. State the observed outcome and its material limitation first. Supply enough
   context to explain why it matters. Describe the user scenario rather than the
   internal component graph when that makes the meaning clearer.
4. Preserve the task revision, product revision, environment, time, criteria,
   evidence, uncertainty, risks, delivery state and acceptance state. Explain a
   historical report separately from newer observations.
5. Correct a false previous conclusion explicitly using available evidence. Do
   not preserve a mistake for formal consistency or call a factual correction
   merely cosmetic. Unknown facts remain unknown.
6. Explain terminology using the relevant project scope. Mark hypothetical
   examples as examples, never as measurements from the current task.

The request grants no authority to modify code, run tests, start agents, deploy,
commit, push, change criteria or rewrite a glossary. Read sources and return the
explanation. Persist an explanatory artifact only when separately authorized.
Do not claim that previously running processes stopped without observing that.

Acknowledging understanding does not accept the product or approve a scope change.
The same facts rendered twice are not two successful checks. Record a presentation
relationship only when the existing report ledger supports it; do not invent a
second execution receipt or replace historical records.

If source context is missing, identify the missing facts and explain what is known.
Do not force the user to specify a confusing word when a full explanation is
already possible. A full repeated report retains every mandatory condition; an
abbreviated one says so and never omits material negative information.
