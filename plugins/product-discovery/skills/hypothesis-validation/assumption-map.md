# Assumption Map

An assumption is a proposition the decision relies on but that has not been established for the stated scope. Keep assumptions separate from observations and from the decision itself.

For each assumption, record:

| Item | Question |
| --- | --- |
| Assumption | What must be true for the proposed decision to work? |
| Decision link | Which choice or outcome changes if this is false? |
| Evidence and gap | What supplied evidence bears on it, and what remains unknown? |
| Consequence | What is the consequence of being wrong, including safety or reversibility? |
| Discriminating observation | What observable result would most cheaply distinguish the plausible explanations? |
| Feasibility and limit | Can that result be collected within the allowed scope? What would it not establish? |

Prioritize assumptions whose failure would change a costly or hard-to-reverse decision. Prefer a small, safe check that could change the decision over a large check that merely adds detail. If no feasible observation can discriminate the alternatives, preserve the assumption as unknown and keep the hypothesis in `draft` or state the limit; do not assign an invented numeric probability.

## Example (synthetic)

| Item | Synthetic entry |
| --- | --- |
| Assumption | A short task guide makes the next-step link findable in the fixed sample scenario. |
| Decision link | Whether to retain this guide wording in the synthetic prototype. |
| Evidence and gap | No observations yet; the claim is an assumption. |
| Consequence | A misleading guide could add navigation errors. |
| Discriminating observation | Count link locations and critical navigation errors in each fixed synthetic scenario. |
| Feasibility and limit | A deterministic fixture can exercise the path; it says nothing about real users. |
