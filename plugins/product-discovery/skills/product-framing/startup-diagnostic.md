# Startup Diagnostic

Ask only from declared task inputs and the user's answers in this session. Choose questions by stage and ask each missing question individually. After each question, **STOP** for an answer. Do not convert a prompt into a claim or fill a gap with market research.

## Stage routing

- **Pre-product:** demand reality → status-quo cost → desperate specificity.
- **Has users, not yet paying:** status-quo cost → narrowest paid wedge → observation and surprise.
- **Has paying customers:** narrowest paid wedge → observation and surprise → future fit.

If stage is unknown, ask which description fits and stop. A stage label is only routing context, not proof of demand. Skip a routed question only when supplied inputs already answer it, and cite that input in the brief.

## Six forcing questions

Ask one at a time. Use neutral wording; do not embed the answer, a target value, or a recommendation in the question.

1. **Demand reality:** “What actions, if any, in the declared inputs suggest a need? Which inputs support or contradict that interpretation?”
2. **Status-quo cost:** “What does the affected person or organization do today, including doing nothing? What supplied evidence describes its cost?”
3. **Desperate specificity:** “Which user, if any, is described as experiencing this problem? What supplied input identifies the situation and consequence?” A role or segment without an identified case stays broad; never invent a user.
4. **Narrowest paid wedge:** “What is the smallest separable outcome someone might pay for, and what declared input supports that possibility?” Payment is a hypothesis unless a traceable record establishes it.
5. **Observation and surprise:** “What has someone done with the current solution, and what supplied record shows something unexpected?” Distinguish witnessed behavior from a user's account or a demonstration.
6. **Future fit:** “Which stated change could alter the value of this opportunity, and what supplied evidence connects that change to this problem?” Do not fetch forecasts or assume that a general trend helps.

If an answer is broad, ask one neutral clarification about a concrete instance, timeframe or source. Do not stack follow-up prompts. Record what is known, unknown and contradicted, then stop for the next answer.
