# Builder Brainstorm

Use when the declared inputs include a concrete prototype, codebase, or working capability. Start from what it does and the current task. Ask one open question at a time, then **STOP**.

1. “What outcome does the current capability make possible, based on the supplied description or code?”
2. “What different user, workflow or context could use that same capability?”
3. “What is the smallest change that would let you compare those possibilities?”

Offer a small set of clearly labeled possibilities, not a list framed as validated demand. Invite correction without steering toward the most exciting or most profitable idea. Distinguish ideas generated in this brainstorm from claims grounded in supplied evidence.

Then move to the premise challenge and mandatory alternatives. Preserve the user's original goal alongside any lateral idea. End with an OpportunityBrief and a next discriminating action; a build step is not evidence that anyone wants the result.
